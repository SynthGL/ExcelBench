## `perf`

```bash
uv run excelbench perf --tests <fixture-dir> --output <output-dir> [options]
```

Measures read and write throughput (ops/second) plus RSS memory for each adapter.

### What It Measures

For each library, the perf runner captures:

| Metric | Description |
|--------|-------------|
| Wall time | Elapsed real time (p50, p95, p99) |
| CPU time | User + system CPU time |
| RSS delta | Memory usage increase |
| Throughput | Operations per second (cells read/written) |

### Benchmark Workloads

- **Per-cell read** — iterate cells one at a time (10K cells)
- **Per-cell styled read** — read with formatting attributes (1K cells)
- **Bulk read** — `read_sheet_values()` returning all cells at once (10K cells)
- **Bulk write** — `write_sheet_values()` writing all cells at once (100K cells)

Bulk workloads run only on adapters that implement `read_sheet_values()` or `write_sheet_values()`; for other adapters the harness records the bulk operation as failed. The WolfXL adapter implements both through WolfXL's public worksheet API, not a separate bulk path.

### Options

| Flag | Default | Description |
|------|---------|-------------|
| `--tests` | required | Path to throughput fixture directory |
| `--output` | required | Output directory for perf results |
| `--adapters` | all | Comma-separated adapter names |
| `--iterations` | 5 | Number of iterations per workload |

### Example

```bash
uv run excelbench perf --tests fixtures/excel --output results
```

### Reference Numbers

From the [2026-10-27 perf refresh](https://github.com/SynthGL/ExcelBench/blob/master/results-2026-10-27/perf/README.md) (local date; raw timestamps 2026-10-28 UTC): Apple M5 Pro, Python 3.13.9, 3 warmups, 25 recorded iterations, the same 19 small feature workbooks for every library. Totals sum per-feature p50 wall times, mostly measuring per-call overhead rather than large-file throughput. Each ratio is openpyxl's total divided by the library's total within this run.

| Library | Read p50 total | Read vs openpyxl | Write p50 total | Write vs openpyxl |
|---------|----------------|------------------|-----------------|-------------------|
| WolfXL 2.0.21 | 14.54 ms | 1.52x | 13.73 ms | 2.05x |
| openpyxl 3.1.5 | 22.13 ms | 1.00x | 28.09 ms | 1.00x |
| python-calamine 0.8.2 | 1.75 ms | 12.67x | n/a (read-only) | n/a |
| polars 1.44.2 | 7.24 ms | 3.06x | n/a (read-only) | n/a |
| pandas 3.0.6 | 31.28 ms | 0.71x | 32.80 ms | 0.86x |

WolfXL is measured through its public API (`wolfxl.load_workbook`, `wolfxl.Workbook`), the same kind of surface as every other library. python-calamine leads this small-file read comparison, and polars also reads faster than WolfXL. openpyxl reads and writes faster than pandas. WolfXL's separate [large-file ecosystem results](https://github.com/SynthGL/wolfxl-oss/tree/main/benchmarks/results) use different workloads, APIs, environments, and versions; their ratios are not interchangeable with this lane. This refresh is not a version-isolated comparison with 2026-10-03, which ran on a different host and interpreter.
