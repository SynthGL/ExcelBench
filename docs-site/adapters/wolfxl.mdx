WolfXL is a Rust-backed Python library with an openpyxl-compatible API. ExcelBench drives it through that public API:

| Operation | Public API (WolfXL 2.0.21) | Speed vs openpyxl (2026-10-27 perf refresh) |
|-----------|---------------------------|-------------------|
| Read | `wolfxl.load_workbook(path)` | **1.52x** (14.54 ms vs 22.13 ms) |
| Write | `wolfxl.Workbook()` then `save(path)` | **2.05x** (13.73 ms vs 28.09 ms) |
| Modify | `wolfxl.load_workbook(path, modify=True)` then `save(path)`: patch mode rewrites only the changed sheet XML and copies every other ZIP entry unchanged | No current measurement |

Speed figures sum per-feature p50 wall times over 19 small feature workbooks, mostly measuring per-call overhead, not large-file throughput (3 warmups, 25 recorded iterations, Apple M5 Pro, Python 3.13.9). WolfXL 2.0.21 uses its public API. In the same run python-calamine (12.67x openpyxl) and polars (3.06x) read faster than WolfXL. Source: [2026-10-27 perf results](https://github.com/SynthGL/ExcelBench/blob/master/results-2026-10-27/perf/README.md). WolfXL's [large-file ecosystem results](https://github.com/SynthGL/wolfxl-oss/tree/main/benchmarks/results) measure different workloads and are not interchangeable with these ratios.

## Usage

```python
import wolfxl

# Read
wb = wolfxl.load_workbook("data.xlsx")
ws = wb.active
val = ws["A1"].value

# Write
wb = wolfxl.Workbook()
ws = wb.active
ws["A1"] = "Hello, world"
wb.save("output.xlsx")

# Modify (surgical patch, no full rewrite)
wb = wolfxl.load_workbook("template.xlsx", modify=True)
ws = wb.active
ws["B2"] = 42
wb.save("patched.xlsx")
```

## How Modify Works

Standard Excel libraries rewrite the entire `.xlsx` ZIP archive on save. WolfXL's modify mode instead patches only the changed XML sheets in-place, leaving all other ZIP entries untouched.

Large static content in a template (images, charts, pivot tables) is never parsed or re-serialized when only a few cells change.
