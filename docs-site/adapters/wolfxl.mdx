WolfXL is a Rust-backed Python library with an openpyxl-compatible API. ExcelBench drives it through that public API:

| Operation | Public API (WolfXL 2.0.8) | Speed vs openpyxl (2026-10-03 perf snapshot) |
|-----------|---------------------------|-------------------|
| Read | `wolfxl.load_workbook(path)` | **1.73x faster** (13.90 ms vs 24.01 ms) |
| Write | `wolfxl.Workbook()` then `save(path)` | **2.45x faster** (11.26 ms vs 27.59 ms) |
| Modify | `wolfxl.load_workbook(path, modify=True)` then `save(path)`: patch mode rewrites only the changed sheet XML and copies every other ZIP entry unchanged | No current measurement |

Speed figures are sums of per-feature p50 wall times over the same 19 xlsx features for both libraries (warmup 3, 25 iterations, Apple M4 Pro, Python 3.12.3), measured on WolfXL 2.0.8 through its public API (`wolfxl.load_workbook`, `wolfxl.Workbook`). In the same run python-calamine (13.92x openpyxl) and polars (3.87x) read faster than WolfXL. Source: `results-2026-10-03/perf/README.md`.


## Usage

```python
import wolfxl

# Read
wb = wolfxl.load_workbook("data.xlsx")
ws = wb.active
val = ws["A1"].value

# Write
wb = wolfxl.Workbook()
ws = wb.active
ws["A1"] = "Hello, world"
wb.save("output.xlsx")

# Modify (surgical patch, no full rewrite)
wb = wolfxl.load_workbook("template.xlsx", modify=True)
ws = wb.active
ws["B2"] = 42
wb.save("patched.xlsx")
```

## How Modify Works

Standard Excel libraries rewrite the entire `.xlsx` ZIP archive on save. WolfXL's modify mode instead patches only the changed XML sheets in-place, leaving all other ZIP entries untouched.

Large static content in a template (images, charts, pivot tables) is never parsed or re-serialized when only a few cells change.

## Benchmark Scores

From the 2026-10-03 snapshot (WolfXL 2.0.8): fidelity from `results-2026-10-03/xlsx` (21 scored features; `pivot_tables` is unscored for every adapter), mutation from `results-2026-10-03/mutation`, calc from `results-2026-10-03/calc`, speed from `results-2026-10-03/perf`:

| Axis | Score |
|------|-------|
| Fidelity | 21/21 features green in both read and write, tied with openpyxl 3.1.5 (21/21 read and write) |
| Read Speed | 1.73x openpyxl (WolfXL 2.0.8 public API) |
| Write Speed | 2.45x openpyxl (WolfXL 2.0.8 public API) |
| Feature Coverage | 100% (21/21 features score at least 1 in read or write) |
| Template mutation | Preserved, 17/17 template features kept (openpyxl 16/17) |
| Calc | Community 2.0.8 calculates 133/133 formulas, but its `save()` writes 0/133 calculated values; Commercial 2.3.0 calculates and saves 133/133 |
| Capability Breadth | 100 (R+W+Modify) |

Every scored feature is 3/3 in both read and write, so there are no fidelity gaps in this snapshot.
